## 1. Проблема (от владельца)

1. **Декоративные эмодзи в артефактах.** Заголовки секций отчёта/дайджеста содержат эмодзи (🎯, 🛡, 🔍, 📐…). При экспорте в Google Docs/Obsidian и передаче артефактов другим людям это выглядит неряшливо и мешает чтению.
2. **Атрибуция расплывается.** Реальный кейс: во вводе было «конкуренты **для первоначального сайта** были сделаны **с помощью NotebookLM**», в отчёте появилось «конкуренты … **для платформы портфолио**». Модель перенесла факт на другой объект и потеряла привязку «инструмент → объект».

Цель: артефакты без декоративных эмодзи; каждый факт сохраняет точную связку
«**кто — что — чем — для какого объекта**», если она есть во вводе.

## 3. Раздел «АТРИБУЦИЯ И АВТОРСТВО» (текст для промпта)

Вписать в стиль существующих промптов (русский язык, тон — как в «ГРАНИЦАХ РОЛИ»):

```text
## АТРИБУЦИЯ И АВТОРСТВО

1. АВТОРСТВО. Действие приписывай исполнителю (человек, агент, модель, команда)
   ТОЛЬКО если во вводе явно назван исполнитель. Исполнитель не назван —
   нейтральная формулировка («выполнен анализ», «реализовано») или пометка ❓.
   Запрещено приписывать пользователю или агенту действия, для которых во вводе
   нет явного «я сделал» / «агент сделал».
2. ИНСТРУМЕНТ. Инструмент (NotebookLM, Claude, ChatGPT, Cline, Figma и т.п.)
   привязывай строго к тому объекту и задаче, к которым он отнесён во вводе.
   Переносить упоминание инструмента на другой объект или задачу запрещено.
3. ОБЪЕКТ ФАКТА. Каждый факт прикрепляй к тому проекту/объекту, к которому он
   отнесён во вводе. Во вводе несколько проектов/объектов — не смешивай факты
   между ними. Неясно, к какому объекту относится факт, — помечай ❓ и указывай
   объект явно в формулировке.
4. СВЯЗКА «КТО — ЧТО — ЧЕМ — ДЛЯ ЧЕГО». Сохраняй её целиком: «конкуренты для
   первоначального сайта проанализированы с помощью NotebookLM» не превращается
   в «конкуренты платформы проанализированы». Сокращая формулировку, не теряй
   ограничители (какой сайт/проект, какой инструмент).
5. НЕ РАСШИРЯЙ ОБЛАСТЬ. «Для X» не становится «для X и Y»; «в версии A» не
   становится «во всём проекте».
6. ПРОТИВОРЕЧИЯ. Если во вводе есть противоречия по исполнителю/инструменту/
   объекту — зафиксируй оба варианта с ❓; не выбирай молча.
```

## 6. Ручная проверка владельцем

1. Отчёт на реальном дампе: заголовки без эмодзи; маркеры ✅/❓/❌ на месте.
2. Дамп с фактом «X сделано с помощью Y для Z» → в отчёте связка сохранена, нет переноса на другой объект и нет приписанного авторства.
3. Дайджест и Кейс: без эмодзи; в кейсе `tools`/`my_role` не «размазаны» по чужим объектам.
4. Демо: загружается, соответствует новым правилам.
5. `npm run typecheck` — чисто.
