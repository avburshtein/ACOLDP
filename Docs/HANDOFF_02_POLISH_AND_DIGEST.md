## 1. Зачем этот пакет

После 01 кейс по структуре правильный, но UI всё ещё выглядит как «только Daily Report», а кнопка «В тикеты» торчит на дайджесте и кейсе (путает дизайнера).  
Дайджест заточен под книги/курсы, а реальный сценарий автора — **дампы чатов с разными LLM**.

Цель: ощущение «инструмент артефактов», не «обёртка над одним отчётом».

## 2. Задачи (порядок)

### 2.1 UI результатов — заголовок по режиму

**Файл:** `src/ui/components/results-panel.tsx`

Сейчас при любом Markdown жёстко:

```text
📋 DAILY REPORT
```

Заменить на заголовок от `view.mode`:

| mode | Заголовок в карточке |
|------|----------------------|
| `REPORT` | `📋 Отчёт` |
| `LEARNING_DIGEST` | `📚 Дайджест` |
| `CASE_DRAFT` | `🎨 Кейс UX42` |
| иное | `MODE_LABELS[mode]` |

В шапке панели уже есть `MODE_LABELS[view.mode]` — не дублировать смысл криво; внутри карточки тоже режимный title.

### 2.2 «В тикеты» только для Отчёта

**Файл:** `src/ui/components/results-panel.tsx`

Кнопку «В тикеты» (`onConvert`) показывать **только если** `view.kind === 'report' && view.mode === 'REPORT'`.

Для `LEARNING_DIGEST` и `CASE_DRAFT` оставить: Google Docs / Copy / Download.

### 2.3 Completeness-баннер для кейса (лёгкий UI)

**Файлы:** `src/ui/components/results-panel.tsx` (+ при необходимости крошечный хелпер `src/ui/lib/parse-case-completeness.ts`)

Если `view.mode === 'CASE_DRAFT'` и в markdown есть секция `## Completeness`:

1. Распарсить строку вида: `Заполнено из ввода: 24/42` (числа гибко: `\d+/\d+`).
2. Опционально взять следующую строку «Требует данных дизайнера: …» (обрезать до ~120 символов + «…» если длиннее).
3. Над `<pre>` с markdown показать компактный баннер (без новой дизайн-системы):

```text
Заполнено 24/42 текстовых полей
Ещё нужно: devices, client, … 
```

Если парсинг не удался — баннер не показывать (не ломать UI).  
**Не** вырезать секцию Completeness из самого markdown — она остаётся в тексте для Docs/копирования.

### 2.4 LEARNING_DIGEST — чаты LLM как первоклассный источник

**Файл:** `src/api/prompts.js` → `LEARNING_DIGEST_SYSTEM_INSTRUCTION`

Точечно дополнить (не переписывать весь промпт):

1. **Input sources** явно включать:  
   `LLM chat dump` / смесь чатов (Claude, ChatGPT, Gemini, Qwen, Cline и т.д.), заметки, статьи, курсы.
2. В YAML `source:` допускать значения вроде:  
   `llm-chat` | `llm-chat-mixed` | `book` | `article` | `course` | `video` | `notes` | `mixed` | `unknown`
3. Правило для чатов:  
   - разделять **идеи / решения / открытые вопросы / расхождения между моделями**;  
   - цитаты помечать источником, если в дампе видно (имя модели / роль);  
   - не выдавать домыслы модели за факты пользователя.
4. В `tags` для chat-дампов желательны теги вроде темы + `llm-chat` при уместности.

**REPORT-промпт не трогать** в этом handoff, кроме бага, блокирующего сборку.

### 2.5 Демо-данные: один вход → три согласованных выхода ⚠️ обязательно

**Проблема сейчас** (`src/ui/demo-data.ts` + кнопка «демо» в `app.tsx`):

| Константа | О чём сейчас | Согласовано? |
|-----------|--------------|--------------|
| `SAMPLE_RAW_INPUT` | Инженерный день Flow: wake_time, alarm, recurring-баг, Gemini 429, i18n, CTA нутрициолога | — |
| `SAMPLE_REPORT` | Отчёт по этому дню | ✅ с raw |
| `SAMPLE_LEARNING_DIGEST` | Книга Kahneman, Fast and Slow | ❌ другой мир |
| `SAMPLE_CASE_DRAFT` | Онбординг Flow, метрики 68%→31%, интервью | ❌ та же «вселенная Flow», но **другой сюжет**, метрик нет во входе |

Гость жмёт демо → видит один текст слева и «магический» несвязанный кейс/дайджест справа. Это ломает доверие к продукту.

**Решение — одна история (рекомендуется):**

Переписать все четыре константы вокруг **одного** сырого дампа: дизайнерский день по кейсу **onboarding Flow** (чаты с Claude/Gemini, заметки исследования, цифры Amplitude, итерации, блокеры). Тогда:

1. `SAMPLE_RAW_INPUT` — хаос дня (даты, цитаты моделей, метрики, решения, открытые дыры).  
2. `SAMPLE_REPORT` — Daily Digest **только из этого** входа (✅/❓ по правилам REPORT).  
3. `SAMPLE_LEARNING_DIGEST` — дайджест обучения из **тех же** чатов/заметок (`source: llm-chat-mixed`, теги про onboarding/UX).  
4. `SAMPLE_CASE_DRAFT` — 8 секций UX42 **только из фактов входа**; чего нет (fonts, cover, имя клиента…) → `❓`.  
   Completeness N/M пересчитать честно под новый текст.

**Правила написания демо:**

- Не выдумывать в CASE/DIGEST факты, которых нет в `SAMPLE_RAW_INPUT`.  
- Метрики (типа 68%→31%) должны **буквально встречаться** во входе.  
- Длина raw: примерно как сейчас (читаемо за 30 сек), не роман.  
- Язык: русский.  
- Кнопка загрузки демо в `app.tsx` по-прежнему подставляет `SAMPLE_RAW_INPUT` — менять API не нужно, если вход один.

**Альтернатива (хуже для гостя):** три пары `SAMPLE_RAW_*` + `SAMPLE_*` по режиму и подставлять input при смене mode в демо — только если один общий дамп окажется слишком натянутым. Предпочтение — одна история.

## 5. Ручная проверка владельцем

1. Режим **Отчёт** → в карточке «Отчёт», кнопка «В тикеты» есть.  
2. Режим **Дайджест** → «Дайджест», «В тикеты» **нет**, экспорт работает.  
3. Режим **Кейс UX42** → «Кейс UX42», «В тикеты» **нет**, над текстом баннер `Заполнено N/M`.  
4. **Демо-согласованность:** загрузить демо-текст → без ключа прогнать Отчёт / Дайджест / Кейс → одна история Flow onboarding; цифры и цитаты из кейса/дайджеста есть во входе; нет Kahneman и чужого инженерного дня без связи.  
5. (Опционально live) свой дамп двух LLM → `source` llm-chat / mixed.
