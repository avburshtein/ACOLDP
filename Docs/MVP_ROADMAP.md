## Критерий «полезного MVP»

Цепочка пользователя не должна рваться:

```
вставил хаос → получил артефакт → НЕ ПОТЕРЯЛ его → довёл до цели
                    (экспорт)      (история)      (Google Docs / Obsidian /
                                                   форма кейса в UX42)
```

Сейчас рвётся в двух местах: (1) генерация падает на длинных входах (524) — не «получил»; (2) результат живёт только в памяти вкладки — «потерял». Пакеты ниже закрывают их в этом порядке.

## Кратко о содержании пакетов

**1. Стриминг + стабильность (HANDOFF 03).** SSE из Worker → UI: текст появляется по мере генерации, первый байт уходит сразу → Cloudflare не отдаёт 524. Кнопка Stop (AbortController), частичный результат сохраняется. Ретраи и полные тексты ошибок для OpenAI-compatible (диагностика GLM 500 — без попытки «починить чужой API»).

**2. История + REFINE.** Сгенерированные артефакты (отчёт/дайджест/кейс) сохраняются локально (IndexedDB, не Worker). Список: дата, режим, заголовок, превью → открыть, переэкспортировать. Кнопка «Дополнить»: текущий артефакт + новый кусок хаоса → регенерация с сохранением уже сделанного (REFINE-промпт: «обнови, не переписывай с нуля»). Это сценарий «выделить важное у одной LLM и добавить у другой».

**3. Кейс → JSON.** Второй LLM-вызов со schema по БД UX42 (`projects` + `project_details`: keyMetrics, personas, comparisons, reviews, projectItems) → кнопка «Скачать .json». Field keys в CASE_DRAFT-промпте уже совпадают со схемой — задел сделан.

**4. Мост в UX42.** В `ux42studio`: импорт `case.json` в Case Study Builder (Server Action создаёт draft; медиа-поля пустые — юзер загружает сам). После этого фича продаётся: «вставь хаос из чатов — получи заполненный черновик кейса в портфолио».

## Сознательно НЕ в MVP (North Star, не сейчас)

Голосовой ввод · разговоры LLM между собой / мультиагенты · Telegram-бот · n8n · векторная БД / RAG · Living Docs Engine · cron-диспетчер · расширение Jira-режима.

Это амбиции из старой спецификации — вернуться после того, как пакеты 1–4 приняты и инструмент живёт в ежедневном использовании.

---

## Процесс

Каждый пакет = один handoff-файл в `Docs/`, прогон через Cline/Claude, ручная приёмка владельцем по чеклисту пакета. Следующий пакет не начинать, пока предыдущий не принят на реальных данных.
