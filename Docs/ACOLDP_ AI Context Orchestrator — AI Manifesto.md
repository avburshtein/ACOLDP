# **ACOLDP: AI Context Orchestrator & Living Documentation Platform**

**AI Manifesto & Vision Document**  
Данный Манифест определяет философию, ключевые стремления, принципы и концептуальную архитектуру платформы **ACOLDP** (AI Context Orchestrator & Living Documentation Platform). Документ служит ориентиром для инженеров, архитекторов и ИИ-коллег, участвующих в развитии экосистемы.

## **1\. Философия Продукта**

Современная разработка с участием искусственного интеллекта столкнулась с фундаментальным барьером: **фрагментацией контекста**. Разговорные интерфейсы (чаты) удерживают знания внутри изолированных диалоговых сессий, приводя к галлюцинациям, потере архитектурных нюансов и повторному объяснению вводных данных при смене модели или сервиса.  
**ACOLDP меняет парадигму:**

> * **Контекст как живой капитал (Living Context):** Знания о проекте — это не исторический архив чатов, а динамический, постоянно актуализируемый ресурс, доступный как людям, так и ИИ-агентам.  
> * **Симбиоз Человек \+ Multi-AI:** Solo-разработчик руководит коллективом узкоспециализированных ИИ-ассистентов (Google Gemini, Anthropic Claude, OpenAI, Qwen), выступая в роли Главного Архитектора.  
> * **Гибридный формат знаний (JSON \+ Markdown):** Передаваемый контекст одинаково эффективно считывается детерминированными ИИ-системами (через структурированные схемы) и человеком (через выразительную разметку).

## **2\. Наша Миссия и Стремления**

> 1. **Нулевые потери контекста (Zero Context Loss):** Гарантировать, что ни одна мысль, зафиксированный баг или архитектурное решение из дневных обсуждений не потеряется при переходе между моделями и сессиями.  
> 2. **Автоматическая трансформация хаоса в порядок:** Превращать неотструктурированный поток дайджестов, логов и файлов в строгие дневные отчёты и атомарные задачи для трекеров (Jira).  
> 3. **Ультимативная автономность Solo-инженера:** Предоставить одному человеку мощь и производительность целой кросс-функциональной команды за счёт интеллектуальной оркестрации.

## **3\. Архитектура и Компоненты Платформы**

Платформа строится на принципах максимальной легковесности, отказоустойчивости и независимости от тяжелых серверов (Serverless / Edge-first).

| Компонент | Назначение | Технологический стек   |
| :---- | :---- | :---- |
| **Edge Core & Web UI** | Единый управляющий узел (All-in-One), предоставляющий пользовательский интерфейс и обрабатывающий запросы. | Cloudflare Workers / Pages, Native JS & CSS (Google Stitch UI) |
| **Daily Digest Architect** | Модуль анализа дневного контекста, выявления блокеров, ошибок API и формирования структурированного Markdown-отчёта. | Google Gemini API (2.5 / 2.0 Flash Series) |
| **Jira Intelligence Layer** | Семантический анализ задач, дедупликация, создание тикетов и автоматическое обновление бэклога без дублирования. | Atlassian Jira REST API v2, Dynamic JSON Schema Validation |
| **Multi-LLM Fallback Engine** | Каскадное переключение между моделями при сбоях 503, превышении квот 429 или отсутствии эндпоинтов 404\. | callGeminiWithRetry, Gemma, Qwen, Custom API Endpoints |

## **4\. Заповеди Манифеста (Core Principles)**

> * **Принцип 1\. Детерминированность поверх хаоса.** Любой вывод для ИИ-коллег должен опираться на четкие JSON-схемы, а для людей — на понятную структуру.  
> * **Принцип 2\. Локальность и приватность ключей.** Все персональные ключи (API Keys, Tokens) должны принадлежать пользователю и храниться в локальной среде (localStorage), исключая несанкционированную передачу.  
> * **Принцип 3\. Непрерывность работы (Resilience).** Ошибка одного API или исчерпание квоты конкретной модели не должны останавливать рабочий процесс — система обязана переключаться на резервные каналы.  
> * **Принцип 4\. Живая документация (Living Documentation).** Документация не пишется "на потом" — она рождается автоматически из ежедневного процесса разработки и выполненных задач.
